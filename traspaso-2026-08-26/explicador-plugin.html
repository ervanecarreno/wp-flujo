Cómo funciona wp-generateblocks

Convierte en herramienta instalable lo que costó caro aprender en un proyecto real: el flujo de 8 fases para webs WordPress con GeneratePress + GenerateBlocks Pro, con validadores, puerta de calidad y wp-cli listos de fábrica.

00

El problema que resuelve

En el proyecto que originó este plugin, el marcado de GenerateBlocks pasó su checklist de validación sin un solo error. El sitio, aun así, llegó roto a producción.

Marcado validado

0 / 179

Bloques con errores de sintaxis, según el checklist de validación del propio marcado.

Imágenes en producción

11 / 13

Daban 404 en el sitio real: las rutas no contaban con el subdirectorio del dominio.

Validar el marcado y validar el entorno son comprobaciones distintas. Un archivo de bloques puede ser perfectamente canónico y estar roto en el sitio de destino. wp-generateblocks existe para que esa segunda comprobación deje de depender de acordarse.

01

Las 8 fases del flujo

El orden importa: cada fase se apoya en hechos que la anterior deja verificados. Prioridad fija en todas ellas — velocidad → menos pasos → fiabilidad del prototipo.

0

Bootstrap del entorno

nueva

Se monta el WordPress vacío antes del diseño — ~10 min. Se anota subdirectorio, breakpoint real de GeneratePress (768px) vs GenerateBlocks (767px) y carpeta de uploads. Diseñar a ciegas de esto fue la causa raíz del fallo de arriba.

1

Diseño directo en HTML

Sin partir de Figma para extraer código: el límite de uso del Figma MCP se ata al plan del archivo del cliente, no al del que trabaja. El sistema de color se fija como variables CSS reales desde este momento.

2

Esqueleto de portabilidad

Git en wp-content/, tema hijo, CPTs por código, acf-json/ activo desde el día uno — es gratis, no requiere PRO — y carpeta /patterns/ para las secciones reutilizables.

3

Repositorio

Con el alcance correcto: solo lo de la fase 2. Nunca el core de WordPress, uploads/ ni plugins de terceros.

4

Generación de marcado

Imágenes subidas primero con wp media import --porcelain para usar IDs reales. Color siempre por clase CSS utilitaria, nunca elegido en el panel del bloque.

5

Plantillas y contenido dinámico

Noticias, CPT, listados. Las secciones ya viven en /patterns como PHP, no como contenido pegado que solo existe en la base de datos.

6

Animación con GSAP

GenerateBlocks Pro no anima por scroll — su panel Effects es solo hover/focus. Sobre listados dinámicos: re-consultar el DOM y refrescar ScrollTrigger siempre, nunca una captura fija.

7

Puerta de calidad

nueva

Contra el sitio ya desplegado, con la URL real y su subdirectorio — nunca contra un HTML local. Es la comprobación que habría detectado el fallo de la fase 00.

Enlaces e imágenes rotas → peso de imagen → accesibilidad WCAG 2.1 AA → rendimiento (CLS / LCP) → salud de WordPress.

8

Producción

wp search-replace --dry-run --skip-columns=guid primero, revisar el informe, y solo entonces repetir sin --dry-run. Nunca editar URLs a mano.

02

Las 4 skills

Cada una se activa por un disparador distinto, sin solaparse entre sí. Ninguna duplica contenido de los documentos del repo — apuntan a ellos.

flujo-wordpress-generateblocks

El enrutador

Se activa al aparecer un proyecto WordPress de cliente.

Las 8 fases, las cinco trampas ya pagadas y lo descartado con fundamento (Figma como fuente, GenerateCloud, theme.json sin verificar).

generar-bloques-generateblocks

El generador

Al escribir o corregir marcado de bloques GB.

El método de referencia, el checklist de 10 casillas, y obliga a pasar el validador antes de dar nada por bueno.

wp-cli-en-local

El puente

Antes de proponer cualquier comando wp o php.

Local WP ya trae ambos dentro. Nunca hay que decirle al usuario que le falta wp-cli: lo tiene, solo hay que saber dónde.

puerta-calidad-wordpress

El guardián

Antes de entregar o publicar un sitio.

Los cinco pasos de la fase 7, contra la URL real. La que existe precisamente porque el marcado perfecto no bastó una vez.

04

Caso real: el bug que encontró el propio plugin

El 27/08/2026 se probó si var(--color) sobrevive al guardado real de WordPress. La respuesta importante no fue la esperada.

figma-staging · GenerateBlocks Pro 2.7.0 · sandbox puntual
✕ Con 5 escapes (incluidas las comillas → \u0022), WordPress guardaba el bloque vacío. El saneado de seguridad de WordPress no reconocía el comentario como un bloque legítimo — sin ningún error visible.
✓ Con 4 escapes y comillas literales, el bloque sobrevive intacto — incluido var(--color) hasta el CSS real del frontend. 
# parse_blocks() de WordPress, antes y después de corregir el escapado
attrs: Array ( )                          ← con el quinto escape: vacío

attrs: Array (
    [styles] => Array ( [background-color] => var(--color-x) )
    [css] => .gb-element-x{background-color:var(--color-x)}
)                                          ← con los 4 escapes correctos: intacto

El validador propio del plugin nunca exigió ese quinto escape — siempre fue correcto. El error vivía solo en la documentación, y ya está corregido en los cinco sitios donde aparecía.

05

Cómo se usa, en el día a día

Se instala una vez por máquina. A partir de ahí, las skills se activan solas al detectar contexto de proyecto WordPress.

01

Añadir el repositorio como marketplace: /plugin marketplace add C:\TRABAJOS\wp-flujo

02

Instalar wp-generateblocks desde el menú /plugin → Discover.

Si el otro proyecto trae la skill de cuenta antigua, desactivarla antes: compite con las de este plugin.

03

Trabajar como siempre. Al mencionar WordPress, GeneratePress o GenerateBlocks, la skill del flujo se activa sola.

04

Antes de entregar: node herramientas/puerta-calidad.js https://sitio.com/

05

Si el repo cambia (nuevas skills, herramientas corregidas), actualizar desde /plugin → Installed → Update para que el plugin instalado recoja los cambios.
