Setup WordPress + GenerateBlocks

El flujo definitivo, en 8 fases, para webs de cliente con GeneratePress + GenerateBlocks Pro V2 + ACF. Nace de la investigación de 7 temas (verificada adversarialmente) y de un experimento propio contra un WordPress real que corrigió dos de sus conclusiones.

§1

Los tres cambios de fondo

Frente a la propuesta original de 7 pasos, estos son los ajustes que de verdad importan — el resto es orden y detalle.

1

El WordPress vacío se monta primero, no después del diseño. El fallo que originó este flujo (rutas rotas por un subdirectorio) fue posible precisamente porque el diseño se cerró sin conocer los hechos del entorno real. Montar el sitio vacío son ~10 min y no bloquea nada.

2

Los tokens de color van en CSS real, no en el panel de color de cada bloque. GenerateBlocks resuelve siempre el color elegido en su selector a HEX literal, confirmado por su propio soporte — así que "cambiar un color" solo puede ser una edición si nunca se fijó bloque a bloque.

3

Hay una puerta de calidad automatizada antes de producción. El marcado del proyecto que originó este flujo era perfecto — 0 errores sobre 179 bloques — y el sitio estaba roto igualmente. Validar el marcado y validar el entorno son dos capas distintas, y las dos hacen falta.

§2

Las 8 fases

Cada fase se apoya en hechos que la anterior deja verificados. Las dos marcadas como nuevas son las que la propuesta original no tenía.

0

Bootstrap del entorno

nueva

Crear el sitio vacío en Local WP con GeneratePress + GenerateBlocks Pro V2 + ACF (free) + plugins específicos. Anotar de inmediato: ¿hay subdirectorio?, ¿qué breakpoint usa GP (768px) vs GB (767px)?, ¿carpeta de uploads? Dejar montado el esqueleto de portabilidad (fase 2) en este mismo paso — más barato vacío que reordenado después.

1

Diseño directo en HTML

Sin partir de Figma para extraer código, con MCP o con token — el límite se ata al plan del archivo del cliente, no a quien llama. Si el cliente ya trae uno, solo como referencia visual. El sistema de color se fija aquí como variables CSS reales, nunca en el panel de color del bloque.

2

Esqueleto de portabilidad

  • git init dentro de wp-content/
  • Tema hijo de GeneratePress, versionado
  • CPTs registrados por código, nunca por plugin de UI
  • acf-json/ activo desde el día uno — gratis, no requiere PRO
  • /patterns/ para secciones reutilizables, vía WordPress core
  • Exportar la configuración del tema y la tipografía con node herramientas/config-tema.js exportar — no están en código, viven en la base de datos, y son lo único de esta fase que el repo no recoge solo
3

Repositorio GitHub

Push del esqueleto de la fase 2, con el alcance correcto: nunca core, uploads/ ni plugins de terceros. Push/pull diario tiene sentido porque lo que se versiona es código de verdad.

4

Generación de marcado

  • Imágenes subidas primero con wp media import --porcelain — un ID inventado no da error, solo deja de generar tamaños responsive
  • Escapado del JSON: 4 sustituciones (--, <, >, &), comillas literales — ver corrección más abajo
  • Color siempre por clase CSS o var() directo en styles/css, nunca por el panel del bloque
  • Validador Node obligatorio antes de dar nada por bueno
5

Plantillas, noticias, CPT

Los CPT ya están registrados por código desde la fase 2. Las plantillas y secciones se guardan como archivos PHP en /patterns, no como contenido que solo vive en la base de datos.

Los query loops se montan aquí, y la animación viene después. Animar una sección con un número fijo de tarjetas y convertirla luego en query loop rompe la animación: los selectores dejan de encajar y las tarjetas del bucle nunca se registran.

6

Animación con GSAP

  • GSAP 100% gratuito desde abril de 2025, incluido ScrollTrigger
  • Encolar vía wp_enqueue_script en el tema hijo, nunca vía WPCode
  • GenerateBlocks Pro no anima por scroll — su panel Effects es solo hover/focus
  • Sobre listados dinámicos: re-consultar el DOM y refrescar ScrollTrigger siempre, nunca un número fijo de tarjetas
  • prefers-reduced-motion no es opcional — exigible por el RD 1112/2018
7

Puerta de calidad

nueva

Contra el sitio ya desplegado en staging, con la URL real y su subdirectorio — nunca contra un HTML local:

  • node herramientas/puerta-calidad.js <url> — enlaces e imágenes rotas contra el servidor real
  • Peso de imagen: <200 KB por imagen above-the-fold; convertir con sharp-cli o avif-cli
  • pa11y-ci + @axe-core/cli contra WCAG 2.1 AA — obligatorio para ayuntamientos
  • lhci autorun — CLS ≤ 0.1, LCP ≤ 2,5s
  • wp doctor check --all — salud general de WordPress
8

Producción

wp search-replace --dry-run --skip-columns=guid primero, revisar el informe, y solo entonces sin --dry-run. Nunca editar URLs a mano. Tras desplegar, repetir la fase 7 completa contra la URL de producción real.

El search-replace arregla las URLs, pero la configuración del tema y la tipografía no llegan solas: reimportar con node herramientas/config-tema.js importar --path=<destino> --confirmar. Sin --confirmar solo informa; con él, deja copia de los valores anteriores. Y luego mirarlo en el navegador: es lo único que ningún validador confirma por ti.

§3

Corrección de hoy: lo que la investigación no pudo saber

La investigación original se hizo por desk research. Esto solo lo reveló probarlo contra un WordPress real.

Corregido 27/08/2026 (tarde)

Se afirmaba: "GenerateBlocks no admite var(--color) de forma fiable en el marcado pegado a mano" — y por eso se recomendaba aplanar todo a valores literales.

Es falso. Verificado contra un WordPress real: var(--color-x) sobrevive intacto — guardado vía la API REST (el mismo camino que el editor), parseado por WordPress, y presente en el CSS que GenerateBlocks genera de verdad en el frontend.

El problema real nunca fue var(): era una quinta sustitución de escapado (comillas → unicode) que ni este documento ni la investigación original sabían que rompía el guardado — con ella, WordPress guarda el bloque vacío, sin ningún error visible. Con las cuatro sustituciones correctas y comillas literales, todo funciona.

§4

Piezas descartadas y por qué

GenerateCloud

$99/año. Solo rentable gestionando muchos sitios con librería de patrones compartida. Para un proyecto puntual, exportar/importar XML es gratis y suficiente.

Global Styles como sincronización

Custom post type sin API REST ni WP-CLI oficial. No hay forma fiable de versionarlo en git — esto no cambia con la corrección de arriba: el problema de Global Styles nunca fue el escapado.

var() en el marcado

Se daba por descartado. Resuelto: sobrevive con el escapado correcto (ver §3). Sigue sin probar un clic real en el CSS Editor de GB Pro 2.6 desde la UI.

theme.json en GeneratePress

Su efecto real en frontend es ambiguo incluso en la documentación oficial. Verificarlo contra el sitio real antes de construir nada encima.
