§0

Antes de escribir nada

Un paso que no es del flujo pero que decide si el flujo funciona: desde dónde abres Claude Code.

La trampa que ya se pagó. Claude Code guarda la memoria en una carpeta cuyo nombre sale de la ruta de trabajo. Si abres el proyecto desde otra ruta —o mueves la carpeta— la memoria anterior queda huérfana y empiezas de cero sin darte cuenta. Cada proyecto, siempre desde su misma ruta.

# la carpeta del proyecto de cliente, no la del flujo
cd C:\TRABAJOS\reformas-bermudez
claude

El plugin wp-generateblocks ya está instalado en la cuenta, así que sus cinco skills están disponibles aquí sin hacer nada. No hay que copiar el flujo a cada proyecto: va contigo.

§1

El recorrido

Nueve turnos. En cada uno: lo que escribes tú, y lo que hace el plugin.

0

Bootstrap del entorno

skill: flujo
Tú escribes

Proyecto nuevo de cliente: Reformas Bermúdez. Tengo el diseño aprobado en Figma: una home y una sección de servicios que será un CPT. Acabo de crear el sitio en Local WP, se llama reformas-bermudez. Empezamos.

Con solo mencionar un proyecto WordPress de cliente se activa la skill del flujo. Lo primero que hace no es maquetar: es preguntarte por el entorno, porque los tres datos de abajo condicionan todo lo que venga después y salen gratis ahora.

  • ¿Hay subdirectorio? Aquí no: irá en la raíz del dominio. Anotado.
  • Breakpoint real: GeneratePress usa 768px y GenerateBlocks 767px. Se elige uno y se anota como fuente única de verdad.
  • Carpeta de uploads: 2026/08 este mes.

Si intentas saltar a maquetar sin esto, la skill te frena. Es deliberado: es el error que costó caro en el proyecto Aridane, donde el diseño se cerró a ciegas y luego 11 de 13 imágenes daban 404 en producción.

1

Del diseño al HTML

aquí el plugin no llega
Tú escribes

El diseño está aprobado. Te paso las capturas de la home y los tokens de color y tipografía que usa.

Este es el único paso que el plugin no cubre. El flujo empieza cuando el marcado ya existe: no traduce Figma a GenerateBlocks. Figma vale como referencia visual —capturas, medidas, comentarios— nunca como fuente del código.

Y no es un olvido. El límite de la API de Figma se ata al plan del archivo del cliente, no al tuyo, y la API de Variables exige Enterprise. Un flujo que dependa de eso se rompe en el primer cliente que no pague el plan. Para ese paso tienes tu propio pipeline, aparte.

Lo que sí se decide aquí, y es lo que importa para las fases siguientes: el color se fija como variables CSS reales en la hoja de estilos del tema hijo. Nunca elegido en el panel de color de cada bloque.

Por qué esto no es una manía. GenerateBlocks resuelve a HEX literal cualquier color elegido en su panel —confirmado por su propio soporte—. Si el azul del cliente se elige bloque a bloque y luego pide cambiarlo, no es una edición: es repasar 179 bloques a mano.

2

Esqueleto de portabilidad

3 herramientas
Tú escribes

Vamos con la fase 2. Prepara el esqueleto: quiero el CPT de servicios y la tipografía del tema ya configurada.

Aquí se monta todo lo que tiene que poder viajar del portátil a producción. Es la fase más aburrida y la que decide si la entrega será tranquila o un domingo de trabajo.

  • git init dentro de wp-content/
  • Tema hijo de GeneratePress, versionado
  • El CPT de servicios, registrado por código, en un plugin propio
  • acf-json/ activo desde el minuto uno — es gratis, no requiere PRO
  • /patterns/ para las secciones reutilizables

El CPT va aquí, no al final. En tu supuesto original los servicios aparecían como último paso. Si se deja para el final, la sección de servicios se construye dos veces: una a mano para el diseño y otra cuando llega el CPT. Registrarlo ahora, vacío, cuesta diez minutos y ahorra rehacer la sección.

Y el paso que cierra la fase, el más fácil de olvidar porque no se ve:

# con el tema ya configurado: colores, tipografía, espaciados
node herramientas/config-tema.js exportar --path="C:\Users\David\Local Sites\reformas-bermudez\app\public"

=== EXPORTAR configuracion del tema ===
  Sitio:      C:\Users\David\Local Sites\reformas-bermudez\app\public
  WordPress:  6.9.1   (MySQL en el puerto 10023)
  Destino:    C:\TRABAJOS\reformas-bermudez\config-tema

  OK       generate_settings   (configuracion del tema) - 214 claves
  OK       generate_spacing_settings   (espaciados) - 18 claves
  OK       generate_package_font_library   (tipografia) - 3 claves

--- TAMBIEN HAY ESTO EN LA BASE DE DATOS, Y NO SE LLEVA (2) ---
  generate_package_secondary_nav
      activacion de modulos de GP Premium: revisa que el destino tenga licencia
  theme_mods_generatepress-child
      lleva IDs de adjunto (logo, favicon): los IDs no coinciden entre sitios

Si alguna de esas hace falta:  --incluir=generate_package_secondary_nav

Por qué existe este comando. La configuración del tema y la tipografía no están en ningún fichero: viven en la base de datos. El repo se lleva el tema hijo, los CPT y los patrones, así que sin este paso el destino recibe la maqueta correcta con la tipografía y los espaciados de fábrica. El diseño llega roto y no hay ningún error que lo avise.

Fíjate en que lista dos opciones y no las toca. Solo exporta las tres que están verificadas; lo demás lo enseña para que decidas tú. El theme_mods, por ejemplo, lleva dentro el ID del logo — y ese ID no existirá en producción.

git add config-tema
git commit -m "Configuración del tema y tipografía"

Y cada vez que retoques la tipografía o un espaciado: volver a exportar. Es el equivalente a guardar.

3

Repositorio

Push del esqueleto. Nunca el core de WordPress, nunca uploads/, nunca plugins de terceros: sus versiones se anotan en un README en vez de comitear binarios. A partir de aquí el push diario tiene sentido, porque lo que se versiona es código de verdad y no un volcado de base de datos.

4

Generación del marcado

skill: bloques
Tú escribes

Monta la sección hero de la home: imagen de fondo, titular, subtítulo y dos botones. Te paso la captura y las imágenes.

Se activa la segunda skill, la del método de bloques. Y lo primero que hace es subir las imágenes, antes de escribir una línea de marcado:

herramientas\wp-cli\wp.cmd media import obra-salon.jpg --porcelain --path=$sitio
312

herramientas\wp-cli\wp.cmd media import cocina-abierta.jpg --porcelain --path=$sitio
313

Ese 312 es el ID real, y es el que va al marcado. Un ID inventado en el prototipo no da ningún error: simplemente deja de generar los tamaños responsive, y la imagen llega pesando cuatro veces lo que debería.

El fallo silencioso de detrás. Si el PHP no tiene cargadas las extensiones gd y exif, wp media import sube la imagen pero tampoco genera los tamaños — y también calla. El envoltorio wp.cmd del plugin ya las carga; es la razón de que exista en vez de usar wp a secas.

Luego se genera el marcado y se valida antes de pegarlo, no después:

node herramientas/audit-gb.js secciones/hero.html

Bloques analizados: 7
ERRORES: 0
Avisos: 3  (texto suelto en bloques `text` hijos: falso positivo conocido)

Solo importan los errores. Lo que comprueba, bloque a bloque: que el css reconstruido desde styles coincide carácter a carácter, que el escapado del JSON es correcto, que htmlAttributes es un objeto y no un array —causa número uno del temido «este bloque contiene contenido inesperado»—, y que los uniqueId no se repiten.

Un detalle que costó encontrar. El escapado del JSON son cuatro sustituciones: --, <, > y &. Las comillas se dejan literales. Durante meses la documentación pedía una quinta —escapar las comillas— y era justo la que rompía el guardado: WordPress guardaba el bloque vacío, sin un solo mensaje de error. El validador nunca la exigió, así que siempre estuvo bien; el fallo estaba en el papel.

5

Servicios y noticias: los query loops

Tú escribes

La home ya está montada. Ahora la rejilla de los 6 servicios tirando del CPT, y las 3 últimas noticias del blog abajo.

El CPT ya existe desde la fase 2, así que la rejilla se monta directamente como query loop: no hay que deshacer nada. Las plantillas y secciones se guardan como ficheros PHP en /patterns, no como contenido pegado que solo vive en la base de datos y no viaja.

Y aquí va el orden que importa: los query loops primero, la animación después. Es la otra corrección a tu planteamiento original. Si animas una rejilla de 6 tarjetas fijas y luego la conviertes en query loop, la animación se rompe: los selectores dejan de encajar y las tarjetas que llegan del bucle no se registran nunca. Se ve perfecto en tu pantalla y roto en cuanto el cliente añade un servicio.

6

Animación con GSAP

Tú escribes

Ahora sí: quiero que las tarjetas de servicios entren al hacer scroll, y el hero con un fundido al cargar.

  • GSAP es 100% gratuito desde abril de 2025, ScrollTrigger incluido
  • Se encola con wp_enqueue_script en el tema hijo, nunca con WPCode: WPCode vive en la base de datos y no viaja entre entornos
  • GenerateBlocks Pro no anima por scroll — su panel Effects es solo hover y focus. Está confirmado dos veces por su propio soporte, así que no hay que volver a buscarlo
  • Sobre contenido que viene de un bucle: re-consultar el DOM y refrescar ScrollTrigger, nunca guardar una lista de nodos y confiar en ella
  • prefers-reduced-motion no es opcional: es exigible por el RD 1112/2018
7

Puerta de calidad

skill: puerta
Tú escribes

Ya está subido a staging. Pásale la puerta de calidad.

Contra el sitio desplegado de verdad, con su URL real. Nunca contra un HTML local: el entorno es justo lo que rompe, y un fichero en tu disco no tiene entorno.

node herramientas/puerta-calidad.js https://staging.reformasbermudez.es/ --max-kb=200

--- ROTAS EN TU SITIO (1) - las que bloquean la entrega ---
  [404] imagen  https://staging.reformasbermudez.es/wp-content/uploads/2026/08/equipo-obra.jpg

--- ROTAS HACIA FUERA (1) - revisar, no siempre es culpa tuya ---
  [0] enlace  https://www.colegiooficial-ejemplo.org/directorio

--- IMÁGENES POR ENCIMA DE 200 KB (2) ---
    418 KB  .../obra-salon.jpg
    236 KB  .../cocina-abierta.jpg

=== RESUMEN ===
  URLs comprobadas:   64
  Rotas en tu sitio:  1   <- las que bloquean la entrega
  Rotas hacia fuera:  1
  Imágenes pesadas:   2

Esa imagen en 404 es el fallo que ningún validador de marcado puede ver: el marcado es perfecto, la imagen no está. En Aridane fueron 11 de 13, con cero errores de marcado sobre 179 bloques.

Fíjate en la separación. Lo roto en tu sitio bloquea la entrega. Lo roto hacia fuera —una web ajena caída— se informa y no bloquea nada: no tiene sentido no entregar porque el servidor de otro esté de mantenimiento.

La skill te recuerda además los tres pasos que este script no cubre, y que descargan software la primera vez, así que te pide permiso antes: pa11y-ci y @axe-core/cli para accesibilidad WCAG 2.1 AA, lhci autorun para rendimiento, y wp doctor check --all para la salud del WordPress.

8

Producción

config-tema, otra vez
Tú escribes

Aprobado por el cliente. Vamos a producción.

# siempre en seco primero, y leer el informe
wp search-replace "http://reformas-bermudez.local" "https://reformasbermudez.es" --dry-run --skip-columns=guid

Nunca editar URLs a mano: WordPress guarda URLs absolutas por diseño intencional. Y entonces, el paso que cierra el círculo de la fase 2:

# sin --confirmar no escribe nada: solo te dice qué haría
node herramientas/config-tema.js importar --path=$produccion

--- SE VA A SOBRESCRIBIR ESTO (3) ---
  generate_settings                 distinta: se sobrescribe
  generate_spacing_settings         no existe aqui: se creara
  generate_package_font_library     no existe aqui: se creara

=== NO SE HA ESCRITO NADA ===
Esto sobrescribe la configuracion del tema del sitio destino, y eso no se
deshace solo. Si es lo que quieres, repite el comando anadiendo --confirmar
(se guarda copia de lo actual antes de tocar nada).

Se lee, y solo entonces se repite en serio:

node herramientas/config-tema.js importar --path=$produccion --confirmar

  Copia de lo anterior en: config-tema\copias-previas\2026-09-04T11-42-08

  OK       generate_settings
  OK       generate_spacing_settings
  OK       generate_package_font_library

=== COMPRUEBALO EN EL NAVEGADOR ===
Abre el sitio y confirma tipografia, colores y espaciados.

Y para terminar, repetir la fase 7 completa contra la URL de producción real. Con el subdirectorio si lo hubiera — aquí no lo hay, pero es donde se cae la mitad de las entregas.

Lo único que ninguna herramienta confirma por ti: que el sitio se vea bien. Abre la home y mira la tipografía, los colores y los espaciados. Todo lo demás está automatizado precisamente para que te quede tiempo de hacer esto con calma.

§2

Cuando algo falle

Los cuatro mensajes que vas a ver de verdad, y qué significan. Ninguno es misterioso una vez sabes cuál es cuál.

El mensajeQué pasa en realidad
mysqli_real_connect(): conexión denegada El sitio está parado en Local. Arráncalo con Start site. Si ya está arrancado, es el puerto: Local da uno propio a cada sitio, y las herramientas del plugin lo resuelven solas leyendo su sites.json.
This does not seem to be a WordPress installation El --path está mal escrito o mal entrecomillado. Tiene que acabar en \app\public. Si la ruta lleva espacios, guárdala en una variable de PowerShell primero.
missing the MySQL extension El php.ini del plugin no se está aplicando. Suele pasar tras actualizar Local, porque cambia la versión de PHP y con ella la ruta.
«Este bloque contiene contenido inesperado o no válido» El editor de WordPress rechazando el marcado. Pásalo por audit-gb.js: en la práctica siempre es htmlAttributes como array en vez de objeto, o el escapado del JSON.

Un aviso sobre un falso amigo. wp core version responde tan tranquilo con el sitio apagado, porque lee un fichero y no la base de datos. No sirve para comprobar si el WordPress está vivo. Para eso: wp option get siteurl. Este documento lo menciona porque el propio script cayó en la trampa el primer día.

§3

Lo que hace y lo que no

Sí hace

Te obliga a fijar el entorno antes de diseñar. Genera marcado de GenerateBlocks canónico y lo valida antes de que llegue al editor. Te da wp-cli y PHP funcionando sin instalar nada. Lleva la configuración del tema de un sitio a otro. Y comprueba el sitio desplegado contra el servidor real, no contra tu disco.

Sobre todo: guarda las trampas ya pagadas para que no se vuelvan a pagar. Cada aviso de este documento salió de un fallo real, no de una buena práctica leída en un blog.

No hace

No traduce Figma a GenerateBlocks: el flujo empieza cuando el marcado ya existe. No diseña por ti. No sustituye a mirar la web con tus ojos antes de entregarla.

Y no sincroniza los Global Styles de GenerateBlocks Pro entre entornos, porque hoy no hay forma fiable de hacerlo: no tienen API REST ni comando de wp-cli. Eso sigue siendo un paso manual de checklist antes de cada entrega.
