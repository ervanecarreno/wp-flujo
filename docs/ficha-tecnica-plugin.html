Antes de nada

Qué te estoy pasando

No es un tema ni un plugin de WordPress: es la maquinaria que Claude Code usa en los proyectos de WordPress. Vive en su propio repo (C:\TRABAJOS\wp-flujo) y se instala una vez como plugin de Claude Code; a partir de ahí, cada proyecto de cliente lo hereda sin volver a tocarlo.

Trae el criterio (qué hacer y en qué orden), las skills que lo activan solas, y las herramientas Node que hacen el trabajo sucio — generar el esqueleto, validar bloques, desplegar el tema, medir una web de referencia — para que no dependa de que alguien se acuerde del paso.

Stop hook

Solo aquí dentro

commit-memoria.sh versiona la memoria de Claude al cerrar cada turno — pero solo trabajando en este repo. En un proyecto de cliente no se dispara: ese repo tiene su propio git, aparte.

Una vez por máquina — nunca por proyecto

Instalación

  1. Añade el marketplace. /plugin marketplace add C:\TRABAJOS\wp-flujo — la ruta ya trae .claude-plugin/marketplace.json, no hace falta nada más. Esto solo registra el catálogo: le dice a Claude dónde mirar, sin instalar nada todavía.
  2. Instala el plugin. /plugin install wp-generateblocks@metropolis-wp — el segundo paso, porque un catálogo puede contener varios plugins y este coge uno. A partir de aquí, sus skills están disponibles en cualquier proyecto que abras, no solo en este repo: al empezar una web nueva no se escribe nada de esto.
  3. Mantenlo al día. claude plugin update wp-generateblocks@metropolis-wp, y reinicia Claude Code. Instalar hace una copia, no un enlace vivo: editar este repo no cambia lo que Claude carga. Es el único comando que se repite en el tiempo — cada vez que el plugin cambia, no cada vez que empiezas un proyecto. claude plugin list dice en qué versión estás.
  4. Desactiva la skill vieja de la cuenta. Si existe web-para-wordpress en tu cuenta, apágala — empuja a theme.json y ACF Blocks, justo lo contrario de lo que concluyó la investigación de este flujo.

Lo que pasa cada vez, sin que lo pidas

El ciclo por proyecto

Abres Claude Code dentro de un WordPress de cliente y mencionas GeneratePress, GenerateBlocks, "maquetar una landing" o "pasar a producción": la skill flujo-wordpress-generateblocks se activa sola, sin que la llames por nombre. A partir de ahí, marca la fase en la que estás y avanza así:

00

Bootstrap del WordPress vacío

/wp-nuevo-proyecto

~10 minutos, antes de diseñar nada. Anota subdirectorio, el desfase de breakpoint entre GeneratePress (768) y GenerateBlocks (767), y la carpeta de uploads. El generador monta el esqueleto — nunca a mano, copiando de otro proyecto.

01

Diseño y punto de decisión

skill

HTML directo, handoff ya convertido, o Figma solo si expone variables con nombre. Aquí se pregunta siempre: GenerateBlocks Pro V2 (llega estilada) o Gutenberg nativo (un token cambia toda la página). No lo decide Claude solo.

02

Esqueleto

skill

git init en wp-content/, tema hijo con el contrato de diseño dentro, /patterns/, CPT por ACF solo si hacen falta, y la configuración del tema exportada — no vive en código por defecto.

03

Repositorio

skill

Solo lo de la fase 2 entra al repo. Nunca el core de WordPress, nunca uploads/, nunca plugins de terceros.

04

Marcado

skill

Imágenes primero, con IDs reales. Color siempre por clase CSS, jamás desde el panel del bloque. El validador tiene que pasar antes de seguir; si viene de Figma, el toolkit de conversión hace de puente.

05

Plantillas y CPT

skill

Las secciones repetibles van a /patterns como PHP versionado, no pegadas a mano en la base de datos.

06

Animación con GSAP

skill

Solo si el proyecto la necesita, y siempre después de la fase 5. Una herramienta instala una biblioteca de siete clases ya-funcionan; si hace falta escribir GSAP a mano, las 8 skills vendorizadas de GreenSock enseñan la API correcta en vez de improvisarla.

07

Puerta de calidad

/wp-verificar

Contra la URL real, servida, subdirectorio incluido — nunca contra un HTML suelto. Contrato sincronizado, los dos validadores, round-trip con WordPress, y el contrato ya publicado: el paso que más se olvida y el único que caza "declarar no es publicar".

08

Producción

skill

wp search-replace --dry-run primero, nunca URLs editadas a mano. La configuración del tema se reimporta aparte: el search-replace no la trae.

Los dos que se invocan a mano

Comandos

/wp-nuevo-proyecto

Levanta el esqueleto de un proyecto de cliente con el flujo Figma → GenerateBlocks ya montado. Pide solo lo que no puede deducir: sistema de diseño, slug del plugin, sitio de Local WP, puerto MySQL.

/wp-verificar

Corre la cadena de comprobación completa del proyecto activo — contrato, los dos validadores, round-trip y contrato ya publicado — usando el verificar.mjs que el generador dejó puesto.
